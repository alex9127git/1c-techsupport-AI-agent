# Дорожная карта развития AI-агента техподдержки 1С

Документ описывает приоритетные направления развития прототипа после сдачи.
Разделы упорядочены по соотношению «ценность для бизнеса / затраты».

## 1. Расширение каналов коммуникации

Сейчас поддержка ведётся через Bitrix24 и Redmine HelpDesk. Ожидаемый
охват пользователей растёт при добавлении:

- **Telegram** — самый дешёвый канал (Bot API, никаких вебхуков-плагинов);
- **Email (IMAP)** — тикет-система через почту техподдержки;
- **Веб-виджет на корпоративном портале** — тот же сценарий, что и тестовый
  чат в панели, но со стороны сотрудника 1С.

Каждый канал подключается по одному паттерну: REST-приёмник события →
`AgentService.answer_question(channel=...)` → отправка ответа обратно.
Каналы уже описаны в таблице `channels`, новых сущностей не требуется.

## 2. Онбординг и управление базой знаний

- **Источники в ответе уже показываются**; следующий шаг — «обучение на
  успешных кейсах»: после подтверждения оператором эскалации, документ
  «вопрос → решённый ответ» автоматически добавляется в базу знаний.
- **Версионирование документов**: замена файла не должна ломать индексы —
  переиспользовать существующую идемпотентную индексацию по хешу
  (`rag/database.py`).
- **Пре-модерация загрузок**: NER/парсинг на входе, проверка дублей.

## 3. Метрики эффективности для бизнеса

- Авто-решение % (уже есть на дашборде), среднее время ответа (есть),
  доля эскалаций по каналам (добавить фильтр по `channel` в `/api/logs`,
  поле уже пишется).
- **CSI-опросник**: в конце диалога короткий опрос (оценка 1–5),
  результаты — на дашборд.
- Разрез «по конфигурациям 1С» (ERP / ЗУП / УТ) по тегам документов.

## 4. Связка с подсистемами 1С

- **Интеграция с 1С:Предприятие** (HTTP-сервисы): агент получает структуру
  метаданных конкретной базы, что повышает точность ответов по конкретной
  конфигурации (а не «в общем»).
- **Автосоздание обращений в 1С**: эскалированный вопрос автоматически
  создаёт заявку в системе учёта ИТ (Redmine уже покрывает, добавить 1С:ИТС).

## 5. Масштабирование RAG и качества ответов

- **PostgreSQL вместо SQLite** — уже поддержано `DATABASE_URL` (строки в
  `.env.example`); для больших объёмов добавить векторный поиск внутри БД
  либо отдельный QDrant/PGVector.
- **A/B-тестирование промптов**: метрика качества ответов при изменении
  system-промпта (варианты хранить в `settings`).
- **Гипотеза: несколько моделей**: быстрая (для типовых вопросов) и точная
  (для эскалаций) — маршрутизация по уровню уверенности.

## 6. Безопасность и администрирование

- **Ограничение API-ключей**: аутентификация вебхуков Bitrix/Redmine
  (секрет в заголовке), rate-limit для `/api/chat`.
- **Аудит действий операторов**: логирование ручного перехвата диалога и
  правок базы знаний.
- **Backup/Restore** для volumes `db/`, `data/docs`, SQLite (или PostgreSQL):
  cron-снапшоты в объектное хранилище.

## Порядок внедрения

1. Метрики по каналам + подпись источников (дёшево, уже частично готово).
2. Telegram-канал (быстрый выигрыш по охвату).
3. Обучение на кейсах операторов (повышает авто-решение %).
4. PostgreSQL + резервное копирование (готовность к продакшен-нагрузкам).
5. Интеграция с 1С (глубокая адаптация к конфигурациям).
6. A/B промптов и мультимодельный роутинг (тонкая настройка качества).
